`@glucoseiq/core`, then add a package when your application needs its API.

All published packages require Node.js 24 or newer. The React package keeps a
`react >=18` peer range and is the only package with a React boundary.

## Start with core

Install only the engine when you own the UI, use another framework, or run
analytics in a server process:

```bash
npm install @glucoseiq/core
```

The root export covers the main data model and analytics. Four public subpaths
group APIs by responsibility:

- `@glucoseiq/core/metrics` for individual metrics
- `@glucoseiq/core/connectors` for supported payload normalizers
- `@glucoseiq/core/interop` for interoperability helpers
- `@glucoseiq/core/render` for optional SVG-string renderers

See the [core API reference](/docs/api/core) for the public contract.

## Add packages by boundary

Use [React](/docs/react) when React owns presentation, [tokens](/docs/tokens)
when your design system owns rendering, [testing](/docs/testing) for synthetic
fixtures, and the [CLI](/docs/cli) for file-oriented terminal workflows. The
[API reference](/docs/api) lists each package's public exports.

Install only the packages your application uses. The package boundaries show
which code belongs in browser bundles and which dependencies affect upgrades.
