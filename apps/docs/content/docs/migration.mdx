---
title: Migrating from diabetic-utils
description: Move from diabetic-utils 1.5.x to its 2.0 compatibility bridge or adopt @glucoseiq/core 1.0 directly.
---

## Choose a migration path

GlucoseIQ 1.0 publishes the headless engine as `@glucoseiq/core`. The
`diabetic-utils` 2.0 package re-exports that public API so projects on 1.5.x
can upgrade without changing source imports:

```ts typecheck
import { calculateEnhancedTIR, estimateGMI } from 'diabetic-utils' // still works
```

Upgrade the existing dependency when you want the compatibility path:

```bash
npm install diabetic-utils@^2
```

New projects should install the scoped package:

```bash
npm install @glucoseiq/core@^1
```

```ts typecheck
import { calculateEnhancedTIR, estimateGMI } from '@glucoseiq/core'
```

Use the scoped package for new subpath imports such as
`@glucoseiq/core/connectors`, `@glucoseiq/core/metrics`,
`@glucoseiq/core/interop`, and `@glucoseiq/core/render`.

## Runtime requirement

GlucoseIQ 1.0 and `diabetic-utils` 2.0 require Node 24 or newer. Projects that
cannot upgrade Node can remain on `diabetic-utils` 1.5.x through the `legacy`
dist-tag:

```bash
npm install diabetic-utils@legacy
```

## Numeric behavior and intentional corrections

Conversion and metric formulas keep their 1.5.x numeric behavior except where
this guide identifies an intentional correction. GlucoseIQ 1.0 makes several
boundary and data-quality decisions explicit:

- Enhanced and pregnancy TIR reject zero and non-finite glucose values.
  Pregnancy results now expose the `<54 mg/dL` (`<3.0 mmol/L`) subset as
  `belowRangeLevel2`.
- Population target checks use unrounded percentages. TIR must be strictly
  greater than 70% for the standard population or 50% for older/high-risk
  populations. TBR and TAR checks are cumulative, with their Level 2 subsets
  assessed separately. `targetBasis` reports whether those percentage goals
  were applied to consensus or caller-configured ranges.
- Older/high-risk checks use total TBR `<1%`, Level 2 TBR `<1%`, total TAR
  `<50%`, and Level 2 TAR `<10%`.
- Active percent counts occupied timestamp slots rather than raw rows. Exact
  duplicates and multiple readings in one slot count once, invalid timestamps
  are excluded, and threshold flags use the unrounded ratio.
- Enhanced and pregnancy TIR summary duration is occupied five-minute-slot
  coverage. Quality fails closed for invalid, duplicate-only, or less-than-70%
  timestamp coverage. Each occupied slot is divided across its distinct
  observations and ranges, exact duplicates count once, invalid timestamps add
  no duration, and primary range durations conserve the covered total.
- Glucose string guards accept only positive finite values in a supported unit,
  and GMI option guards require a positive finite value plus the exact
  `mg/dL` or `mmol/L` unit literal.
- Enhanced TIR rejects unsupported runtime population and reading-unit values;
  pregnancy TIR also rejects unsupported unit options instead of selecting a
  fallback target model.
- `analyzeGlucose` and `glucoseIQScore` keep their sentinel-result behavior by
  screening unsupported-unit rows alongside other unusable readings.

Episode detection returns timestamp-grouped candidates that satisfy the
configured threshold, duration, and gap rules. It does not prove a recovered or
clinically adjudicated event.

Percentiles use nearest-rank by default, while interpolation remains opt-in.
Golden-value tests preserve cited results across the package move.

`getA1CCategory` has one intentional boundary correction in
`@glucoseiq/core` 1.0 and the `diabetic-utils` 2.0 compatibility bridge. The
[CDC defaults](https://www.cdc.gov/diabetes/diabetes-testing/prediabetes-a1c-test.html)
classify A1C below 5.7% as normal, 5.7% to below 6.5% as prediabetes, and 6.5%
or higher as diabetes. Explicit custom maxima remain inclusive. The published
`diabetic-utils` 1.5.x artifacts are unchanged, retain their previous boundary
behavior, and remain available via the `legacy` dist-tag.

## Changes in the compatibility major

1. **Node ≥24** for the GlucoseIQ package ecosystem and compatibility bridge.
2. **Typed errors** — intentional throws are now `GlucoseIQError` subclasses
   with stable `code`s. Messages are byte-identical; only `instanceof` narrows
   differently (e.g. GRI's `RangeError` → `DomainError`).
3. **Corrected FHIR LOINC codes** — earlier releases used transposed/invalid
   codes; all codes are now verified against the HL7 CGM IG v1.0.0 value set.
   If you stored Observations with the old codes, re-emit them.
4. **Libre unit fix** — LinkUp payloads with `GlucoseUnits: 0` (mmol/L) are no
   longer mislabeled as mg/dL.
