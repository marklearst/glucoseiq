---
title: Migrating from diabetic-utils
description: Move from diabetic-utils 1.5.x to its 2.0 compatibility bridge or adopt @glucoseiq/core 1.0 directly.
---

## Choose a migration path

GlucoseIQ 1.0 publishes the analytics package as `@glucoseiq/core`. The
`diabetic-utils` 2.0 package re-exports that public API so projects on 1.5.x
can upgrade without changing source imports:

```ts typecheck
import { calculateEnhancedTIR, estimateGMI } from 'diabetic-utils' // still works
```

Upgrade the existing dependency when you want the compatibility path:

```bash
npm install diabetic-utils@^2
```

New projects should install the scoped package:

```bash
npm install @glucoseiq/core@^1
```

```ts typecheck
import { calculateEnhancedTIR, estimateGMI } from '@glucoseiq/core'
```

Use the scoped package for new subpath imports such as
`@glucoseiq/core/connectors`, `@glucoseiq/core/metrics`,
`@glucoseiq/core/interop`, and `@glucoseiq/core/render`.

## Runtime requirement

GlucoseIQ 1.0 and `diabetic-utils` 2.0 require Node 24 or newer. Projects that
cannot upgrade Node can remain on `diabetic-utils` 1.5.x through the `legacy`
dist-tag:

```bash
npm install diabetic-utils@legacy
```

## Behavior changes in 1.0

Several formulas and validation rules change in this major release. Review the
sections below before comparing stored results or snapshot output.

### GMI calculations

`estimateGMI` now uses the published equation for mean CGM glucose:
`3.31 + 0.02392 × mean mg/dL`. Values supplied in mmol/L are converted to
mg/dL before the equation is applied, so equivalent concentrations return the
same result. The public `GMI_COEFFICIENTS` values now match that equation.
`A1C_SLOPE` and `A1C_INTERCEPT` remain as deprecated aliases for the mg/dL
coefficients; they are not A1C-to-GMI coefficients.

| Call | diabetic-utils 1.5.x | GlucoseIQ 1.0 and diabetic-utils 2.0 |
| --- | ---: | ---: |
| `estimateGMI(100, 'mg/dL')` | 5.4% | 5.7% |
| `estimateGMI(5.5, 'mmol/L')` | 12.1% | 5.7% |
| `a1cToGMI(7)` | 3.48 | 7.0 |

`a1cToGMI` remains available for source compatibility, but it is deprecated.
It now maps laboratory A1C through estimated average glucose before applying
the GMI equation. That result is a compatibility transform, not a CGM-derived
GMI. It and `estimateEAG` now reject non-positive or non-finite A1C input. New
code should call `estimateGMI` with measured mean CGM glucose.

### Enhanced and pregnancy Time in Range

Enhanced and pregnancy TIR reject zero and non-finite glucose values. Pregnancy
results expose the `<54 mg/dL` (`<3.0 mmol/L`) subset as
`belowRangeLevel2`.

Population target checks use unrounded percentages. TIR must be strictly
greater than 70% for the standard population or 50% for older/high-risk
populations. TBR and TAR checks are cumulative, with their Level 2 subsets
assessed separately. Older/high-risk checks use total TBR `<1%`, Level 2 TBR
`<1%`, total TAR `<50%`, and Level 2 TAR `<10%`.

`targetBasis` reports whether percentage goals were applied to consensus or
caller-configured ranges. Enhanced TIR rejects unsupported population and
reading-unit values at runtime. Pregnancy TIR also rejects unsupported unit
options instead of selecting a fallback target model.

### Coverage and duration

Active percent counts occupied timestamp slots rather than raw rows. Exact
duplicates and multiple readings in one slot count once, invalid timestamps
are excluded, and threshold flags use the unrounded ratio.

Enhanced and pregnancy TIR summary duration uses occupied five-minute-slot
coverage. Quality fails closed for invalid, duplicate-only, or less-than-70%
timestamp coverage. Each occupied slot is divided across its distinct
observations and ranges, exact duplicates count once, invalid timestamps add no
duration, and primary range durations conserve the covered total.

### Validation and sentinel results

Glucose string guards accept only positive finite values in a supported unit.
GMI option guards require a positive finite value plus the exact `mg/dL` or
`mmol/L` unit literal.

`analyzeGlucose` and `glucoseIQScore` keep their sentinel-result behavior by
screening unsupported-unit rows alongside other unusable readings.

Episode detection returns timestamp-grouped candidates that satisfy the
configured threshold, duration, and gap rules. It does not prove a recovered or
clinically adjudicated event.

Percentiles use nearest-rank by default. Set the interpolation option when you
need type-7 percentiles.

### A1C categories

`getA1CCategory` uses corrected default boundaries in `@glucoseiq/core` 1.0 and
the `diabetic-utils` 2.0 compatibility bridge. The
[CDC defaults](https://www.cdc.gov/diabetes/diabetes-testing/prediabetes-a1c-test.html)
classify A1C below 5.7% as normal, 5.7% to below 6.5% as prediabetes, and 6.5%
or higher as diabetes. Explicit custom maxima remain inclusive. The published
`diabetic-utils` 1.5.x artifacts are unchanged, retain their previous boundary
behavior, and remain available via the `legacy` dist-tag.

## Compatibility package changes

| Area | Change | Action |
| --- | --- | --- |
| Runtime | The package requires Node 24 or newer. | Upgrade Node or remain on `diabetic-utils@legacy`. |
| Typed errors | Throws now use `GlucoseIQError` subclasses with stable `code`s. Messages are byte-identical, but `instanceof` can narrow differently, such as GRI's `RangeError` changing to `DomainError`. | Prefer the stable error `code` when handling failures. |
| FHIR LOINC codes | Earlier releases used transposed or invalid codes. The new codes match the HL7 CGM IG v1.0.0 value set. | Re-emit stored Observations that contain the old codes. |
| Libre units | LinkUp payloads with `GlucoseUnits: 0` are now labeled mmol/L. | Review code that compensated for the earlier mg/dL label. |
